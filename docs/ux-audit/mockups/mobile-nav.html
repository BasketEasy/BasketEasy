Pourquoi une barre basse

  • Le contexte d’usage est un gymnase. Une main libre, un téléphone tenu bas, une lumière médiocre : une cible de 44 px en bas d’écran bat un bouton burger en haut à droite.
  • L’état actif redevient visible. Le traitement de nav actif de Parquet (bg-orange-tint + filet orange) existe déjà ; il n’est simplement jamais visible sur mobile puisque le panneau est fermé la plupart du temps.
  • Le nombre d’items est fixe (4). Le header actuel ajoutait un lien conditionnel par club administré avant l’item 3 du plan d’audit ; la barre basse ne peut structurellement pas repartir dans cette direction.
  • Le header reste pour le sélecteur de club (admin), le titre de contexte et l’avatar — il perd seulement le burger et la liste de liens.

Conflit avec CLAUDE.md — à arbitrer

  • Le jeton shadow-nav-active vaut inset 0 -2px 0 : un filet bas. Dans une barre basse, le filet doit être en haut de l’item. Conformément à la règle « tout jeton vit dans tailwind-preset.cjs », cela demande un jeton nommé (nav-active-top), pas un shadow-[inset_0_2px_0_…] au point d’appel.
  • Les icônes de la barre doivent venir de @basketeasy/ui/icons/* avec une prop tone : aucune classe text-* au point d’appel. Trois icônes manquent aujourd’hui (maison, personne, cloche).
