Ce qui change vs. aujourd’hui

  • La décision remonte. Aujourd’hui le badge « Convoqué par le coach » et le contrôle RSVP sont rendus après le lien retour, le <h1>, la ligne de badges et la carte héros (EventDetailPage.tsx:284-318) : sur un écran de 390 px il faut faire défiler pour répondre. Ici, c’est le premier bloc après le héros.
  • La convocation est une phrase, pas un badge. « Inès vous a retenue dans le groupe des 12 » dit qui, quoi, et combien — myConvocation est un booléen (events.ts:36), l’UI doit fournir le sens.
  • « S’y rendre » est une section à part entière. Aujourd’hui event.location est une InfoTile de texte brut (EventDetailPage.tsx:375-391) : aucun lien d’itinéraire, alors que « comment j’y vais » est la deuxième question d’un joueur, surtout à l’extérieur.
  • « Qui vient ? » est visible sans changer d’onglet. Aujourd’hui c’est l’onglet « Effectif » (EventDetailPage.tsx:444-451) — un mot qui désigne le trombinoscope de l’équipe, pas la liste des présents de ce soir.
  • Les onglets disparaissent pour la joueuse. Aperçu/Effectif/Vote/Feuille de match (EventDetailPage.tsx:333-338) découpaient une page qui, sans les outils de gestion, tient d’un seul tenant.

Nouveaux besoins API

  • Compteurs RSVP agrégés sur l’événement (rsvpSummary) : aujourd’hui la répartition n’existe qu’en dépliant GET …/rsvps (EventRosterTab.tsx), donc jamais « au-dessus de la ligne ».
  • Échéance de réponse (rsvpDeadline) — « avant vendredi 20h » n’existe nulle part dans Event (schema.prisma:185-207).
  • Adresse structurée ou géocodée. location est une chaîne libre ; un lien d’itinéraire peut s’en contenter (encodeURIComponent), pas une distance ni un plan.
