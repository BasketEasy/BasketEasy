# Kluvo — Frontend Technology Stack

Builds on `architecture.md`'s frontend layer (React SPA, TanStack Query, Context, react-hook-form + zod, i18n FR-default). This fills in the concrete picks.

## Core

| Concern         | Choice                | Why                                                                                   |
| --------------- | --------------------- | ------------------------------------------------------------------------------------- |
| Framework       | React 18 + TypeScript | team familiarity, largest ecosystem                                                   |
| Build tool      | Vite                  | fast dev/HMR, simple SPA setup (no SSR need — internal/club-auth app, not SEO-driven) |
| Package manager | pnpm                  | fast, disk-efficient                                                                  |
| Routing         | react-router-dom v6   | standard, handles nested routes for Club/CTC context + protected routes               |

## Data fetching & server state

| Concern                                     | Choice                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           | Why                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| ------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Query/cache layer                           | TanStack Query                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   | caching, background refetch, optimistic updates for RSVP/scoresheet status                                                                                                                                                                                                                                                                                                                                                                                       |
| Query hook naming                           | `use<Model><Method>`, e.g. `useClubCreate`, `useClubList`, `useClubShow`, `usePlayerUpdate`                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      | model-first name is greppable/sortable by domain across the whole hooks folder                                                                                                                                                                                                                                                                                                                                                                                   |
| Query hook files                            | one hook per file (not grouped into a shared `useClub.ts` with multiple exports)                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 | keeps diffs small and each hook independently locatable/importable                                                                                                                                                                                                                                                                                                                                                                                               |
| Mutation cache updates                      | `queryClient.setQueryData(...)` (or `storeTeamEvent` for a `TeamEvent`) with the mutation response, then invalidate only what the write changed elsewhere; never a key the write just filled, and never a key and then a prefix that already covers it                                                                                                                                                                                                                                                                                                                                           | the response already has the full updated record, so refetching it is a wasted request; a second invalidation of a covered key restarts the first fetch (`cancelRefetch`), so the request goes out twice. `clubs/eventCache.ts` holds the shared helpers and the dependency each one encodes (what an RSVP, a call-up or a roster change moves besides the entry it writes)                                                                                      |
| Mutation cache updates — paginated lists    | Exception to the row above: mutations on a paginated/filtered/sorted list (e.g. club members, players, teams) use `queryClient.invalidateQueries({ queryKey: <list>QueryKey(...) })` instead                                                                                                                                                                                                                                                                                                                                                                                                     | the created/updated/deleted row's correct position across an arbitrary cached `(page, search, sortBy, role, …)` combination isn't derivable from the mutation response alone, and several such cached variants may coexist — invalidating (prefix-matching the base key) refetches every one, including the currently active view                                                                                                                                |
| Mutation cache updates — series-wide writes | Exception to the first row: a rare manager write that reaches many cached entries (event create, edit, time change, delete, FFBB import, a roster change) invalidates the team's `events` prefix, narrowed by `invalidateTeamEvents`/`invalidateRosterDependents`; a frequent per-player write (RSVP, travel mode, wash duty) never does                                                                                                                                                                                                                                                         | a kick-off, a venue or a deletion reaches the RSVP roster, the wash duty and the share message too, and a manager writes it a few times a season; an RSVP is written by every player on every event, so its fan-out is listed entry by entry instead                                                                                                                                                                                                             |
| Freshness                                   | every hook sets a `FRESHNESS` tier (`app/src/api/freshness.ts`): `live` 30 s (co-edited: events, RSVPs, convocations, wash duty), `feed` 60 s (polled or always mounted: notifications, the upcoming agenda), `slow` 10 min (others change it rarely: rosters, lists, settings with derived fields, personas), `static` (immutable, or only changed by mutations that write the cache: the session, club and team records, FFBB links, invite previews, a confirmed scoresheet, audited admin reads); a tier can be a function of the cached data (vote results, scoresheet status, match stats) | `static` is safe only for data nobody else can change: the cache entry is discarded 5 minutes after its last observer leaves (`gcTime`), which is what bounds it for page-scoped data, but a query that is always mounted (header, bottom nav, persona list) is never discarded, so it takes a finite tier. A tier that depends on time compares the _fetch_ time to the cutoff (vote results are final only if read after the window closed), not the clock now |
| HTTP client                                 | bare `fetch`, wrapped in a singleton `ApiClient` class                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           | no dependency; one place to hold base URL, default headers, auth header injection, 401/refresh handling, error normalization                                                                                                                                                                                                                                                                                                                                     |
| Auth token refresh                          | handled inside `ApiClient` (queue requests on 401, refresh, retry)                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               | keeps refresh logic in one class instead of scattered interceptors                                                                                                                                                                                                                                                                                                                                                                                               |
| Realtime (later)                            | none for v1; revisit WebSocket/SSE if chat/live scoreboard gets built                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            | avoid over-building before P1/P2 features ship                                                                                                                                                                                                                                                                                                                                                                                                                   |

## Client/local state & contexts

| Concern                        | Choice                                                                          | Why                                                                              |
| ------------------------------ | ------------------------------------------------------------------------------- | -------------------------------------------------------------------------------- |
| Global UI state                | plain React (Context + useState/useReducer)                                     | no extra dependency; app isn't state-heavy enough to justify a store library yet |
| Auth context                   | React Context (JWT, roles, refresh)                                             | wraps TanStack Query's auth-dependent queries                                    |
| Multi-club/CTC switcher        | React Context, persisted to localStorage, read by `ApiClient` to scope requests | small piece of state, doesn't need more                                          |
| Server cache vs UI state split | TanStack Query owns anything from the API; Context owns everything else         | avoids duplicating server data in client state                                   |

## Forms & validation

| Concern           | Choice          | Why                                                                                                  |
| ----------------- | --------------- | ---------------------------------------------------------------------------------------------------- |
| Forms             | react-hook-form | uncontrolled inputs, good perf for roster/payment forms                                              |
| Schema validation | zod             | shared schemas can mirror backend DTOs (NestJS + class-validator), single source of truth for shapes |

## UI components & styling

| Concern                     | Choice                                                                          | Why                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| --------------------------- | ------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Styling                     | Tailwind CSS                                                                    | fast iteration, consistent design tokens for brand                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| Component primitives        | shadcn/ui (Radix-based)                                                         | you own the generated code directly, so it's fully restylable to the Kluvo brand rather than a black box                                                                                                                                                                                                                                                                                                                                                                                                   |
| Collapsible sections        | `@radix-ui/react-accordion`, wrapped once in `@basketeasy/ui/section-accordion` | headless like Dialog and Tabs, so the keyboard model (Enter/Space, arrows, Home/End) and `aria-expanded`/`aria-controls` come with it; only that file imports it, so a swap stays one file. Used by the manager's match page                                                                                                                                                                                                                                                                               |
| On/off settings             | `@radix-ui/react-switch`, wrapped once in `@basketeasy/ui/switch`               | same family as Checkbox and Tabs: `role="switch"`, `aria-checked` and Space/Enter come with it, track and thumb colours are preset tokens, and only that file imports it. Used by the team page's jersey rotation settings                                                                                                                                                                                                                                                                                 |
| Icons                       | custom icon set                                                                 | brand-specific, avoids a generic library look                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| Component library structure | separate `packages/@basketeasy/ui` package, consumed by the app(s)              | decouples UI kit from app code, reusable if a second frontend (CTC admin, etc.) is added later                                                                                                                                                                                                                                                                                                                                                                                                             |
| Rich text (template editor) | Tiptap (ProseMirror), only through `@basketeasy/ui/template-editor`             | the WhatsApp message templates show variables as atomic chips, and a hand-rolled `contenteditable` breaks on caret placement, IME/predictive input and undo, worst on phones; headless (no styles to fight), minimal extensions (Tiptap 3: `document`, `paragraph`, `text` and `UndoRedo` from `@tiptap/extensions`, which replaced the deprecated `extension-history`; no starter kit), lazy-loaded so only managers download it; the wrapper keeps the model as `{key}` text so a later swap is one file |
| Charts                      | Recharts, only through `@basketeasy/ui/chart`                                   | SVG, MIT, no styling engine (unlike MUI X Charts, which needs MUI + Emotion and keeps zoom/heatmaps in paid tiers); the wrapper keeps colours as tokens (`currentColor` + a tone class) and makes a later library swap one file                                                                                                                                                                                                                                                                            |

## Mobile / PWA

| Concern           | Choice                                                              | Why                                                                |
| ----------------- | ------------------------------------------------------------------- | ------------------------------------------------------------------ |
| PWA               | vite-plugin-pwa                                                     | installable, offline shell for coaches/parents using it pitch-side |

## Testing & quality

| Concern                 | Choice                                                             | Why                                                               |
| ----------------------- | ------------------------------------------------------------------ | ----------------------------------------------------------------- |
| Unit/component tests    | Vitest + React Testing Library                                     | pairs natively with Vite                                          |
| E2E                     | Playwright                                                         | covers RSVP flow, scoresheet upload, payment flow end-to-end      |
| API mocking             | MSW (Mock Service Worker)                                          | mocks NestJS API in dev/tests without a live backend              |
| Linting/formatting      | ESLint + Prettier, typescript-eslint                               | standard                                                          |
| Type-safe API contracts | shared `packages/@basketeasy/types` package, mirroring NestJS DTOs | keeps FE/BE in sync as DTOs evolve, no duplicate type definitions |

## Monorepo

pnpm workspace: `app` + `packages/@basketeasy/ui` (once created) + `packages/@basketeasy/types`, with `server` (NestJS) alongside at the repo root. An Nx layer is the eventual plan for shared tooling (lint/build/test caching) and enforced package boundaries — not yet added to this scaffold.
